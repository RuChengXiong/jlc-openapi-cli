# 服务端契约接口修改计划

> 面向内网服务端开发。客户端 `jlc-openapi-cli` 已完成动态契约加载；本文给出服务端需要新增的
> `/list`、`/detail` 两个接口的完整规范、实现步骤与验收用例。

## 1. 背景与目标

当前 CLI 把 111 个接口契约编译在客户端内，接口新增或调整都需要重新发版。目标：

- 服务端按 `appId + ak` 返回该应用已申请的接口目录；
- 按 `apiUri` 返回单个接口的完整契约（请求/响应参数、示例、错误码、agentGuidance）；
- 客户端本地缓存 6 小时，服务端不可用时回退到过期缓存和内置契约；
- **不改变现有业务接口的 JOP 签名和调用方式**。

已确认的接入方式：

| 项目 | 约定 |
| --- | --- |
| 地址 | 与业务接口同一 `endpoint` |
| 方法 | `POST` |
| 鉴权 | 本期**不要求** JOP 签名；`/list` 用 body 中的 `appId + ak` 识别应用 |
| 成功响应 | HTTP 200，裸 JSON（不加 `code/message/data` 包裹） |
| 失败响应 | HTTP 非 2xx，body 为 `{"code":"...","message":"..."}` |

> 安全提示：`/detail` 不鉴权时，任何知道 `apiUri` 的人都能拉取契约。建议后续给
> `/detail` 增加可选 `appId/ak` 或 JOP 签名；客户端已预留 `appId/ak` 字段，服务端可忽略。

## 2. 接口一：`POST /list`

### 2.1 请求

```http
POST {endpoint}/list
Content-Type: application/json
```

```json
{
  "appId": "<APP_ID>",
  "ak": "<ACCESS_KEY>"
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `appId` | string | 是 | 应用 id |
| `ak` | string | 是 | AccessKey |

### 2.2 成功响应

HTTP 200，直接返回数组，不要包裹：

```json
[
  {
    "businessTypeCode": "SaasERP",
    "businessTypeName": "嘉立创云ERP",
    "apis": [
      {
        "apiUri": "/open/api/saas/erp/projectTaskWorkingHours/delete",
        "apiName": "删除项目工时",
        "apiDescn": "根据业务主键 ID 删除一条项目工时记录",
        "method": "POST",
        "contentType": "json"
      }
    ]
  }
]
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `businessTypeCode` | string | 否 | 业务线编码，如 `SaasERP` |
| `businessTypeName` | string | 是 | 业务线名称，客户端用作分类 |
| `apis` | array | 是 | 该业务线下已授权的接口 |
| `apis[].apiUri` | string | 是 | **与签名路径完全一致**，以 `/` 开头，不含 query |
| `apis[].apiName` | string | 是 | 接口名称 |
| `apis[].apiDescn` | string | 否 | 接口描述 |
| `apis[].method` | string | 否 | `POST` / `GET`；缺失时客户端默认 POST，`/detail` 会校正 |
| `apis[].contentType` | string | 否 | `json` / `multipart`；缺失时默认 json |

要求：

1. 校验 `appId` 与 `ak` 的绑定关系；`ak` 无效返回 401，绑定不匹配返回 403。
2. 只返回该 ak 已申请的接口；不要返回全量接口目录。
3. `apiUri` 必须与验签使用的路径逐字符一致。ERP 保留 `/open/api/saas/erp/...` 前缀。
4. 同一 `apiUri` 只出现一次；按业务线、路径稳定排序。
5. 不返回 sk、内部域名、数据库字段、类名等敏感信息。
6. 空授权返回 `[]`（HTTP 200），不要返回 404。

### 2.3 错误

| HTTP | `code` 示例 | 说明 |
| --- | --- | --- |
| 400 | `INVALID_ARGUMENT` | 缺少 appId/ak 或类型错误 |
| 401 | `INVALID_AK` | ak 不存在或已禁用 |
| 403 | `APP_AK_MISMATCH` | appId 与 ak 不匹配 |
| 429 | `RATE_LIMITED` | 超过限流 |
| 500 | `INTERNAL_ERROR` | 服务端异常 |

错误体：

```json
{ "code": "INVALID_AK", "message": "AccessKey 无效", "traceId": "..." }
```

## 3. 接口二：`POST /detail`

### 3.1 请求

```http
POST {endpoint}/detail
Content-Type: application/json
```

```json
{ "apiUri": "/open/api/saas/erp/projectTaskWorkingHours/delete" }
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `apiUri` | string | 是 | 接口路径，必须与 `/list` 返回一致 |

建议后续增加可选的 `appId`、`ak` 用于权限校验；本期客户端只发送 `apiUri`。

### 3.2 成功响应

HTTP 200，直接返回对象：

```json
{
  "apiUri": "/open/api/saas/erp/projectTaskWorkingHours/delete",
  "apiName": "删除项目工时",
  "apiDescn": "根据业务主键 ID 删除一条项目工时记录",
  "businessTypeCode": "SaasERP",
  "businessTypeName": "嘉立创云ERP",
  "method": "POST",
  "contentType": "json",
  "fileFields": [],
  "input": [
    {
      "name": "projectTaskWorkingHoursId",
      "type": "Long",
      "required": true,
      "desc": "工时记录 id（业务命名，与 bizKey 二选一）"
    }
  ],
  "output": [
    { "name": "code", "type": "String", "required": true, "desc": "响应码" },
    { "name": "message", "type": "String", "required": true, "desc": "响应消息" },
    { "name": "success", "type": "Boolean", "required": true, "desc": "是否成功" }
  ],
  "inputExample": "{\"projectTaskWorkingHoursId\":50001}",
  "outputExample": "{\"code\":\"200\",\"message\":\"success\",\"success\":true}",
  "errorCode": [
    { "name": "200", "type": "Integer", "required": true, "desc": "成功 - 请求成功" },
    { "name": "400", "type": "Integer", "required": true, "desc": "参数错误 - 请求参数不合法" },
    { "name": "401", "type": "Integer", "required": true, "desc": "未授权 - 未登录或 token 失效" },
    { "name": "403", "type": "Integer", "required": true, "desc": "禁止访问 - 无权限访问该接口" },
    { "name": "500", "type": "Integer", "required": true, "desc": "服务器错误" }
  ],
  "agentGuidance": "删除前先调用 detail 接口确认记录存在；该操作不可恢复。",
  "schemaVersion": "1",
  "updatedAt": "2026-11-28T10:00:00+08:00"
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `apiUri` | string | 是 | 必须与请求路径一致；不一致客户端会拒绝 |
| `apiName` | string | 建议 | 接口名称 |
| `apiDescn` | string | 否 | 接口描述 |
| `businessTypeCode` | string | 否 | 业务线编码 |
| `businessTypeName` | string | 建议 | 业务线名称 |
| `method` | string | 是 | `POST` / `GET` |
| `contentType` | string | 否 | `json` / `multipart`；有文件字段时必须为 multipart |
| `fileFields` | string[] | 否 | multipart 的顶层文件字段名；缺失时客户端按 `type=file` 推导 |
| `input` | Field[] | 是 | 请求参数，可为空数组 |
| `output` | Field[] | 否 | 响应参数，可为空数组 |
| `inputExample` | string / object | 否 | 入参示例；**推荐 JSON 字符串**，避免大整数丢精度 |
| `outputExample` | string / object | 否 | 返回示例；**推荐 JSON 字符串** |
| `errorCode` | ErrorCode[] | 否 | 错误码说明 |
| `agentGuidance` | string | 否 | 给 agent 的使用指导，可为空 |
| `schemaVersion` | string | 否 | 契约结构版本，便于后续演进 |
| `updatedAt` | string | 否 | 契约更新时间（ISO 8601） |

要求：

1. 未知 `apiUri` 返回 404；参数缺失返回 400；服务端异常返回 500。
2. `method` 只支持 `POST` / `GET`；`GET` 不能声明 multipart 或文件字段。
3. `apiUri` 必须是规范路径：以 `/` 开头，不含 scheme/host/query/`//`/`..`/空白。
4. `errorCode` 使用 `name/type/required/desc`；客户端也兼容 `code/message/solution`。
5. `inputExample` / `outputExample` 推荐 JSON 字符串；如果返回对象，大整数可能在 JSON
   解析时丢精度。
6. `agentGuidance` 是展示文本，不会被客户端执行；写操作建议标注前置条件、幂等性、
   不可恢复、频控等。

### 3.3 递归字段 `Field`

```json
{
  "name": "modelPriceParamList",
  "type": "List<ModelPriceParam>",
  "required": true,
  "desc": "商品集合",
  "items": {
    "type": "Object",
    "children": [
      { "name": "modelAccessId", "type": "String", "required": true, "desc": "模型业务 id" },
      { "name": "modelCount", "type": "Integer", "required": true, "desc": "数量", "min": 1 },
      {
        "name": "surfaceTreatmentList",
        "type": "List<SurfaceTreatment>",
        "required": false,
        "desc": "表面处理",
        "items": {
          "type": "Object",
          "children": [
            { "name": "craftCode", "type": "String", "required": true, "desc": "工艺编码" }
          ]
        }
      }
    ]
  }
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `name` | string | 是 | 字段名；新契约只写叶子名，不要带点号 |
| `type` | string | 是 | 推荐 CLI 词汇：`string/integer/number/boolean/object/array/file/unknown`；也兼容 Java 类型名 |
| `required` | boolean | 否 | 是否必填，默认 false；兼容 `"true"/"Y"` |
| `desc` | string | 否 | 字段说明 |
| `children` | Field[] | 否 | 对象子字段；只对 `object` 有意义 |
| `items` | string / Field | 否 | 数组元素类型；只对 `array` 有意义 |
| `enum` | string[] | 否 | 枚举值；也兼容逗号分隔字符串 |
| `format` | string | 否 | `datetime` / `date`，或 `yyyy-MM-dd HH:mm:ss` |
| `example` | string | 否 | 字段示例，建议字符串 |
| `min` / `max` | number | 否 | 数值范围 |

数组规则：

- 基本类型数组：`type: "array"`，`items: "String"`（或 `items: { "type": "String" }`）。
- 对象数组：`type: "array"`，`items: { "type": "Object", "children": [...] }`。
- 多维数组：服务端可以递归表达，但客户端只支持一层 `items`；内层会映射为 `unknown` 并告警。
- 同一个字段不要同时出现 `children` 和 `items`。

Java 类型映射（客户端兜底）：

| Java 类型 | CLI 类型 |
| --- | --- |
| `String` / `Char` | string |
| `Integer` / `Long` / `Short` / `Byte` / `BigInteger` | integer |
| `BigDecimal` / `Double` / `Float` | number |
| `Boolean` | boolean |
| `List<X>` / `Set<X>` / `X[]` | array + items |
| `Object` / `Map` / POJO | object |
| `File` / `MultipartFile` | file |
| `Date` / `LocalDateTime` / `Instant` | string + datetime |
| `LocalDate` | string + date |
| 其他 | unknown（允许客户端点号透传） |

### 3.4 错误

| HTTP | `code` 示例 | 说明 |
| --- | --- | --- |
| 400 | `INVALID_ARGUMENT` | 缺少 apiUri 或格式错误 |
| 403 | `FORBIDDEN` | 如果后续增加 appId/ak 权限校验 |
| 404 | `API_NOT_FOUND` | apiUri 不存在 |
| 429 | `RATE_LIMITED` | 超过限流 |
| 500 | `INTERNAL_ERROR` | 服务端异常 |

成功必须是 HTTP 2xx + 合法 JSON；客户端不会把 200 里的错误对象当成成功。

## 4. 实现建议

### 4.1 数据来源

1. 复用现有接口元数据注册表（接口路径、名称、描述、业务线、方法、参数树）。
2. 建立 `apiUri -> 契约` 的只读索引；启动时校验 `apiUri` 唯一且规范。
3. 把内部 DTO 的字段树转换为上面的 `Field` 递归结构；对内部类名、数据库列名做脱敏。
4. `agentGuidance` 可以由接口负责人维护，也可以从现有文档的“注意/约束”段落提取。

### 4.2 权限

- `/list`：按 `appId + ak` 查应用授权表，只返回已授权 `apiUri`。
- `/detail`：本期按 `apiUri` 查询；建议后续增加 `appId/ak` 并复用同一授权表。
- 不要把“契约可见”当成“调用有权限”：业务接口仍由 JOP 签名和开放平台权限校验。

### 4.3 性能与缓存

- 契约数据变化频率低，建议服务端进程内缓存；按 `appId + ak` 缓存 `/list` 结果。
- 可返回 `ETag` / `Cache-Control: private, max-age=21600`，客户端已有自己的 6h 缓存。
- 响应体做大小限制：单接口字段数建议 < 5000，嵌套深度 < 20。

### 4.4 安全

- 必须 HTTPS；限制请求体大小。
- 对 `/list` 按 ak 限流，对 `/detail` 按 IP + apiUri 限流。
- 不返回 sk、内部域名、数据库字段、堆栈。
- 记录审计日志：appId、ak 哈希、接口路径、结果码；不要记录明文 ak。
- 如果 `/detail` 保持不鉴权，建议只在内网/受控网络开放，或增加网关 IP 白名单。

### 4.5 灰度与兼容

1. 先部署 `/list` 和 `/detail`，客户端未拿到服务端契约时会使用内置 111 条，不影响现有调用。
2. 先让少量测试应用接入，核对 `/list` 的 `apiUri` 与签名路径是否完全一致。
3. 再逐步放开；客户端 `--refresh` 可立即拉取新契约。
4. 契约结构只做增量字段；客户端会忽略未知字段。删除/改名 `Field` 字段需要同步通知。

## 5. 验收用例

### 5.1 `/list`

- 合法 appId + ak → 200，返回该应用已授权接口，按业务线分组。
- 无效 ak → 401；appId 与 ak 不匹配 → 403。
- 没有授权接口 → 200 + `[]`。
- 同一 `apiUri` 不重复；ERP 路径保留 `/open/api` 前缀。
- 响应中不出现 sk、内部域名、类名。

### 5.2 `/detail`

- ERP 平铺接口（如 `/open/api/saas/erp/projectTaskWorkingHours/delete`）：
  `input` 为 `Long`，`required=true`，`inputExample` 可解析。
- 3DP `submitOrder`：三层嵌套 + 对象数组，`items.children` 正确。
- ERP `uploadTmpFile`：`contentType=multipart`，`fileFields=["file"]`，文件字段 `type=MultipartFile`。
- 3DP GET 接口：`method=GET`，无文件字段。
- 未知 `apiUri` → 404。
- 返回的 `apiUri` 与请求不一致 → 客户端拒绝（服务端应保证一致）。
- `agentGuidance` 对写操作有明确提示。

### 5.3 客户端联调

```bash
# 目录
jlc-openapi-cli list --refresh --json

# 详情
jlc-openapi-cli detail /open/api/saas/erp/projectTaskWorkingHours/delete --refresh --json

# 只读调用验证签名
jlc-openapi-cli /3dp-open/order/getAllEnableMaterialInfo
```

## 6. 与客户端降级策略的配合

客户端调用顺序：

```text
本地缓存（6h 内） → 服务端 /list 或 /detail → 过期缓存 → 内置 111 条
```

- 服务端返回非 2xx、超时、非法 JSON、字段非法时，客户端会走降级，不会覆盖旧缓存。
- `/list` 缺 appId/ak 时，客户端直接使用缓存/内置，不报错；`--refresh` 时才要求凭据。
- `/detail` 404 且内置存在时，客户端使用内置契约并告警；不存在时退出码 2。
- `invoke` 对内置已有接口默认走内置快路径；要使用服务端最新字段，先 `detail <路径>`
  预热缓存或加 `--refresh`。

## 7. 待确认/后续演进

1. `/detail` 是否增加 `appId/ak` 或 JOP 签名（建议增加）。
2. `/list` 是否直接返回 `method/contentType`（建议返回，减少概览歧义）。
3. 是否需要 `ETag` / 增量更新（当前 6h 全量缓存已够用）。
4. `inputExample/outputExample` 是否统一为 JSON 字符串（建议统一）。
5. 契约变更是否需要版本号/变更通知（建议 `schemaVersion` + `updatedAt`）。
