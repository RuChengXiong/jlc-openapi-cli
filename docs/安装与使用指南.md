# jlc-openapi-cli 安装与使用指南

本指南面向第一次使用嘉立创开放平台 CLI 的用户，覆盖 CLI 安装、凭据配置、SKILL 安装、
在 Claude Code 等智能体中使用、更新与卸载。

> 项目仓库：<https://github.com/RuChengXiong/jlc-openapi-cli>
> 本文中的安装命令均可直接复制使用。

## 1. 两个组成部分

| 组件 | 作用 | 分发方式 |
| --- | --- | --- |
| **CLI** `jlc-openapi-cli` | 负责签名、HTTP 调用、动态契约、JSON 输出 | npm 全局安装 |
| **SKILL** `jlc-openapi-cli` | 告诉 Claude Code / Codex 等智能体何时、如何调用 CLI | `init` 复制到 `~/.jlc-openapi-cli/skill`；也可 `npx skills add` |

建议先装 CLI；执行 `jlc-openapi-cli init` 并保存配置后，会自动把 skill 复制到本地暂存目录，
并打印 Claude Code、Codex、通用 agents 的目标路径。

## 2. 环境要求

| 项目 | 要求 |
| --- | --- |
| Node.js（运行 CLI） | >= 18.17 |
| Node.js（运行 `npx skills`） | >= 22.20 |
| npm | >= 9 |
| 操作系统 | Windows 10/11、macOS、Linux |

检查版本：

```bash
node --version
npm --version
```

## 3. 安装 CLI

```bash
npm install -g jlc-openapi-cli
```

验证：

```bash
jlc-openapi-cli --version
jlc-openapi-cli list --builtin
```

`list --builtin` 使用内置契约、不联网，能看到 `/pcb/order/getOrderPageList` 即安装成功。
不带 `--builtin` 时，`list` 会优先请求服务端 `/list`，6 小时后自动刷新；服务端不可用时
回退到本地缓存或内置契约。

### 全局安装权限问题

如果出现 `EACCES`，不要使用 `sudo npm install -g`。推荐：

- 使用 nvm / fnm 管理 Node；
- 或配置 npm 用户级全局目录：

  ```bash
  npm config set prefix "$HOME/.npm-global"
  # 把 $HOME/.npm-global/bin 加入 PATH
  ```

Windows 默认全局目录是 `%APPDATA%\npm`，通常不需要额外配置。

## 4. 配置开放平台凭据

使用前需要嘉立创开放平台的 `appId`、`ak`（AccessKey）、`sk`（SecretKey）。
在开放平台创建应用后即可获得。

### 4.1 交互式配置（推荐给个人用户）

```bash
jlc-openapi-cli init
```

按提示依次输入 appId、ak、sk、endpoint。sk 输入时不回显；endpoint 直接回车使用生产地址
`https://open-api.jlc.com`。

### 4.2 非交互式配置（推荐给智能体 / CI）

```bash
jlc-openapi-cli init \
  --appId "<APP_ID>" \
  --ak "<ACCESS_KEY>" \
  --sk "<SECRET_KEY>" \
  --endpoint "https://open-api.jlc.com"
```

- 生产环境：`https://open-api.jlc.com`
- 已存在配置文件时追加 `--force` 覆盖。

### 4.3 使用环境变量（不落盘）

适合 CI 或临时使用：

| 环境变量 | 对应字段 |
| --- | --- |
| `JLC_OPENAPI_APP_ID` | appId |
| `JLC_OPENAPI_ACCESS_KEY` | ak |
| `JLC_OPENAPI_SECRET_KEY` | sk |
| `JLC_OPENAPI_ENDPOINT` | endpoint |

```bash
# macOS / Linux / Git Bash
export JLC_OPENAPI_APP_ID="<APP_ID>"
export JLC_OPENAPI_ACCESS_KEY="<ACCESS_KEY>"
export JLC_OPENAPI_SECRET_KEY="<SECRET_KEY>"
```

```powershell
# PowerShell
$env:JLC_OPENAPI_APP_ID = "<APP_ID>"
$env:JLC_OPENAPI_ACCESS_KEY = "<ACCESS_KEY>"
$env:JLC_OPENAPI_SECRET_KEY = "<SECRET_KEY>"
```

### 4.4 配置优先级

1. `--config <path>` 指定的文件
2. 当前目录 `./jlc-openapi-config.json`
3. 用户主目录 `~/.jlc-openapi-config.json`
4. 环境变量按字段覆盖上述文件中的值

`init` 默认写入 `~/.jlc-openapi-config.json`，并尽量设置文件权限为 `0600`
（Windows 依赖用户目录 ACL）。

### 4.5 安全

- 配置文件中是**明文密钥**，不要提交到 Git。
- 项目目录下的 `jlc-openapi-config.json` 建议加入 `.gitignore`。
- 不要把配置文件内容贴到聊天、日志或工单中。

## 5. 安装 SKILL

SKILL 随 npm 包分发。执行 `init` 时会自动复制到 `~/.jlc-openapi-cli/skill`，并打印各智能体的
安装路径。也可以继续用 [skills CLI](https://skills.sh) 从仓库安装。

### 5.0 使用 init 自动暂存（推荐）

```bash
jlc-openapi-cli init
```

输出示例：

```text
Skill 已复制到 ~/.jlc-openapi-cli/skill
安装到智能体：
  Claude Code:  ~/.claude/skills/jlc-openapi-cli
  Codex:        ~/.agents/skills/jlc-openapi-cli（部分版本使用 ~/.codex/skills）
  通用 agents:  ~/.agents/skills/jlc-openapi-cli
```

按输出中的目标路径自行复制，例如 Git Bash / macOS / Linux：

```bash
cp -r ~/.jlc-openapi-cli/skill ~/.claude/skills/jlc-openapi-cli
```

PowerShell：

```powershell
Copy-Item -Recurse -Force "$HOME\.jlc-openapi-cli\skill" "$HOME\.claude\skills\jlc-openapi-cli"
```

不需要自动安装时加 `--no-skill`。

### 5.1 全局安装（skills CLI）

```bash
npx skills add RuChengXiong/jlc-openapi-cli -y -g
```

`-g` 表示安装到用户目录，所有项目可用；`-y` 跳过确认。

只安装到 Claude Code：

```bash
npx skills add RuChengXiong/jlc-openapi-cli -y -g -a claude-code
```

同时安装到 Claude Code 和 Codex：

```bash
npx skills add RuChengXiong/jlc-openapi-cli -y -g -a claude-code -a codex
```

安装到所有已检测到的智能体：

```bash
npx skills add RuChengXiong/jlc-openapi-cli --all
```

安装前先查看仓库里有哪些 skill：

```bash
npx skills add RuChengXiong/jlc-openapi-cli --list
```

### 5.2 项目级安装

去掉 `-g`，skill 会安装到当前项目的 `.claude/skills/`（以及 `.agents/skills/`），
可以随项目提交、团队共享：

```bash
npx skills add RuChengXiong/jlc-openapi-cli -y -a claude-code
```

### 5.3 从本地目录安装（开发或内网）

```bash
cd /path/to/jlc-openapi-cli
npx skills add . -y -g -a claude-code
```

### 5.4 手动安装（不支持 skills CLI 的智能体）

把 `skills/jlc-openapi-cli/` 整个目录复制到对应位置：

| 智能体 | 全局目录 | 项目目录 |
| --- | --- | --- |
| Claude Code | `~/.claude/skills/` | `.claude/skills/` |
| Codex / Cline 等 | `~/.agents/skills/` | `.agents/skills/` |

```bash
mkdir -p ~/.claude/skills
cp -r skills/jlc-openapi-cli ~/.claude/skills/
```

### 5.5 验证 SKILL

```bash
npx skills ls -g
npx skills ls -g -a claude-code
```

应能看到 `jlc-openapi-cli`。

## 6. 验证安装

```bash
# 1. 查看内置接口总数（应为 111：110 个官方文档 + 1 个兼容接口）
jlc-openapi-cli list --builtin --summary --json --compact | jq '.total'

# 2. 按关键词找接口（服务端 /list，缓存 6h）
jlc-openapi-cli list --search BOM

# 3. 查看某个接口的完整契约（服务端 /detail）
jlc-openapi-cli detail /pcb/order/create

# 4. 用真实凭据查询订单
jlc-openapi-cli /pcb/order/getOrderPageList \
  --orderType "examples" \
  --produceCode "Y50504" \
  --orderByFlag true \
  --orderDateBegin "2026-11-11 00:00:00" \
  --orderDateEnd "2026-11-16 18:00:00" \
  --pageSize 10 \
  --pageNum 1 \
  --queryFilterFlag true
```

`list`/`detail` 会在文本或 JSON 的 `contractSource` / `meta.source` 中标注契约来源：
`server`（服务端）、`cache`（本地缓存）、`stale-cache`（过期缓存）、`bundled`（内置）。
看到 `bundled` 且找不到新接口时，检查 `endpoint`、网络或运行 `list --refresh`。

成功时 stdout 返回：

```json
{
  "success": true,
  "code": 200,
  "data": {
    "list": [{ "customerOrderId": 82607537, "produceCode": "Y50504", "orderType": "examples" }],
    "total": 1,
    "pageNum": 1,
    "pageSize": 10,
    "pages": 1
  }
}
```

## 7. 在 Claude Code 中使用

### 7.1 自动触发

安装 SKILL 后，Claude Code 会在任务与 skill 描述匹配时自动加载。可以直接用自然语言：

```text
查询我 2026-11-11 到 2026-11-16 的嘉立创样板订单，订单号 Y50504
```

```text
帮我分页拉取今年所有小批量订单，统计总数量
```

```text
帮我配置嘉立创开放平台：appId 是 xxx，ak 是 xxx，sk 是 xxx
```

```text
查一下 C88374 这个型号在立创商城的库存和阶梯价
```

```text
把 ./bom.xlsx 提交到嘉立创做 BOM 配单，然后查询配单结果
```

```text
分页查询嘉立创云 ERP 里最近的入库单，每页 20 条
```

Claude Code 会先调用 `jlc-openapi-cli list --search <关键词>` 找接口，
再用 `jlc-openapi-cli detail <路径>` 确认参数和 `agentGuidance`，最后执行请求并读取 JSON。

### 7.2 显式调用

在提示中直接点名 skill 或命令：

```text
用 jlc-openapi-cli skill 查询嘉立创订单
```

也可以直接给出命令让 Claude Code 执行：

```text
执行：jlc-openapi-cli /pcb/order/getOrderPageList --orderType examples \
  --orderDateBegin "2026-11-11 00:00:00" --orderDateEnd "2026-11-16 18:00:00" \
  --pageSize 10 --pageNum 1
```

### 7.3 减少权限确认

如果希望 Claude Code 不再逐次确认 CLI 命令，可在项目 `.claude/settings.json`
或用户级设置中加入：

```json
{
  "permissions": {
    "allow": ["Bash(jlc-openapi-cli:*)"]
  }
}
```

只读查询可以放心放行；如果后续接入下单类接口，建议不要加入 allow 列表。

### 7.4 推荐的提示方式

- 明确时间范围（`yyyy-MM-dd HH:mm:ss`）和订单类型（`examples` / `batch`）。
- 需要全部数据时说明“分页取完”，智能体会按 `data.pages` 翻页。
- 不要粘贴真实 sk 到对话中；让 Claude Code 引导你运行 `jlc-openapi-cli init`，
  或提前在终端配置好。

## 8. 在其他智能体中使用

- **Codex**：`npx skills add ... -a codex`，安装到 `~/.agents/skills/`。
- **WorkBuddy 等未内置支持的智能体**：用 5.4 的手动方式复制 skill 目录，并在其
  指令/规则文件中引用 `SKILL.md` 的内容。
- 所有智能体最终都是执行同一条 `jlc-openapi-cli` 命令，因此 CLI 必须已全局安装。

## 9. 更新

### 9.1 更新 CLI

```bash
npm install -g jlc-openapi-cli@latest
# 或
npm update -g jlc-openapi-cli
jlc-openapi-cli --version
```

### 9.2 更新 SKILL

`init` 会把最新 skill 复制到暂存目录：

```bash
jlc-openapi-cli init --force
```

然后按 5.0 打印的目标路径重新复制到智能体目录。也可以继续使用：

```bash
npx skills check          # 检查是否有更新
npx skills update -g -y   # 更新全局 skill
```

也可以重新执行一次 `npx skills add ... -y -g`。

### 9.3 固定版本

```bash
npm install -g jlc-openapi-cli@0.3.0
npx skills add RuChengXiong/jlc-openapi-cli@v0.3.0 -y -g
```

### 9.4 契约缓存

- 位置：`~/.jlc-openapi-cli/contracts-cache.json`；
- TTL：6 小时；
- 立即刷新：`jlc-openapi-cli list --refresh` 或 `jlc-openapi-cli detail <路径> --refresh`；
- 完全离线：`jlc-openapi-cli list --offline` / `--builtin`；
- 自定义目录：`JLC_OPENAPI_CACHE_DIR=/path jlc-openapi-cli list`。

缓存只保存接口契约，不保存 sk；目录缓存的键包含 appId/ak 的哈希。

## 10. 卸载

```bash
npm uninstall -g jlc-openapi-cli
npx skills remove --global jlc-openapi-cli
rm -rf ~/.jlc-openapi-cli           # skill 暂存 + 契约缓存
rm -f ~/.jlc-openapi-config.json   # 如不再需要凭据
```

## 11. 输出与退出码

| 退出码 | 含义 |
| --- | --- |
| 0 | 成功 |
| 1 | 业务失败（`code !== 200` 或 `success === false`），stdout 仍有服务端响应 |
| 2 | 用法 / 配置错误 |
| 3 | 网络错误、超时、HTTP 非 2xx |
| 4 | 内部错误 |

- 成功数据输出到 **stdout**。
- 错误与警告输出到 **stderr**，为单行 JSON：

  ```json
  {"error":{"type":"usage","message":"参数 --pageSize 不能大于 100"}}
  ```

## 12. 常见问题

### `jlc-openapi-cli: command not found`

确认 npm 全局 bin 在 PATH 中：

```bash
npm prefix -g
```

把输出的目录（Windows 通常是 `%APPDATA%\npm`，macOS/Linux 通常是
`/usr/local` 或 `~/.npm-global`）下的 `bin` 加入 `PATH`。

### 安装 CLI 时报 `EACCES`

使用 nvm/fnm，或配置用户级 prefix，不要用 `sudo`。

### 提示缺少配置

```bash
jlc-openapi-cli init --appId ... --ak ... --sk ...
```

或设置 `JLC_OPENAPI_*` 环境变量。

### 签名失败 / 401 / `code: 1000`

- 检查本机系统时间是否准确（签名使用秒级时间戳）；
- 确认 endpoint 与凭据环境一致（生产 / 测试）；
- 确认 appId 与 ak/sk 属于同一个应用。

### `HTTP 429`

开放平台返回“接口请求已超过 API 每天额度限制”，等待次日额度恢复或联系嘉立创。

### Git Bash 下接口路径被改写

MSYS 会把 `/pcb/...` 转成本地路径。设置：

```bash
export MSYS_NO_PATHCONV=1
```

或使用不带前导 `/` 的写法：

```bash
jlc-openapi-cli pcb/order/getOrderPageList --orderType examples ...
```

### `npx skills` 报 Node 版本过低

skills CLI 需要 Node.js >= 22.20。升级 Node 后重试，或改用 5.4 的手动安装。

### `skills add` 提示没有检测到智能体

显式指定目标：

```bash
npx skills add <owner>/jlc-openapi-cli -y -g -a claude-code
```

- [ ] 没有在聊天、日志、截图中暴露 sk
- [ ] CI 中使用环境变量而不是把密钥写入仓库

- [ ] `~/.jlc-openapi-cli/contracts-cache.json` 只包含契约，不包含 sk；共享机器上注意目录权限
